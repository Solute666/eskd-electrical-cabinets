# Согласованная модель проекта

## Приоритет исходных данных

Сначала прочитать текущие файлы пользователя. Затем сопоставить последние явные решения, принятую версию схем, спецификацию и документацию изготовителя. Новая дата файла сама по себе не доказывает, что все решения в нём актуальны. Вести внутренний реестр расхождений. Не смешивать оформление одной версии, электрический состав другой и размеры третьей без явного разбора.

Принятие листа фиксирует его состояние для последующих правок; оно не доказывает допустимость каждого электрического решения. При противоречии с документацией аппарата выделить конкретное соединение и источник. Не переносить спорное решение в новый проект как шаблон.

## Минимальные данные

Хранить один согласованный набор таблиц/JSON. Формат допустимо адаптировать к существующему проекту, не вводить вторую независимую базу.

| Сущность | Необходимые поля |
|---|---|
| Аппарат | Уникальная позиция с принадлежностью шкафу; модель/модификация; ссылка на спецификацию; питание; группа; источник данных. |
| Физический вывод | Уникальный внутренний идентификатор; аппарат; точная заводская надпись; сторона и позиция; программный адрес отдельно; допустимые проводники. |
| Провод | Собственный идентификатор записи; номер электрической цепи; два непосредственных конца; шкаф; сечение; цвет; назначение. |
| Кабель | Обозначение; откуда/куда; число и сечение жил; занятые/резервные жилы; экран; наружный диаметр; длина либо «после трассировки». |
| Клемма | Шкаф, группа и номер; тип; две стороны; местный провод; внешний кабель/жила/устройство; перемычка; резерв. |
| Лист и участок | Стабильный идентификатор; номер листа; название; тип документа; ссылки; статус принятия; ревизия. |
| Размещение | Габариты и монтажный контур из источника; система координат; рейка; положение; зона обслуживания/охлаждения; вид и масштаб. |
| Закупка | Артикул; установленное количество; число одинаковых шкафов; общий запас; наличие у заказчика; единица измерения. |

Номер цепи допустимо повторять на электрически общей цепи. Номер строки таблицы соединений не является уникальной маркировкой каждого провода. Для повторяющихся заводских надписей использовать уникальные внутренние идентификаторы, не добавляя вымышленные суффиксы на аппарат.

## Обязательная сверка

1. Проверить перечень аппаратов и совместимость модификаций. Изменение реле затрагивает колодку, расположение выводов, число контактов, защиту катушки, габарит и ведомости; заменить только текст модели недостаточно.
2. Сверить каждый физический вывод с документацией. Для ПЛК сопоставить заводскую надпись и программный адрес, тип выхода и общие выводы. Не выводить способ подключения из внешнего сходства моделей.
3. Сверить граф соединений: непосредственные концы проводов, отдельные кабельные жилы, перемычки клемм, резервы. Незадействованный контакт/резерв не считать подключённым. Не терять экран при преобразовании модели в таблицу.
4. Проверить назначение питания, полярность, совместимость DI/DO, тип и режим AI/AO, развязку интерфейсов, экраны, PE и функциональное заземление FE. FE не заменять сигнальным общим без документации.
5. Для цепей безопасности читать схему именно применённого аппарата и режима: входы, тестовые выходы, ручной сброс, обратная связь, выходы, снятие штатных перемычек. Не подавать внешний потенциал на неизвестный вывод по догадке. Из одного контакта кнопки не делать заявление о двух независимых каналах.
6. Проверять минимальные/максимальные коммутируемые нагрузки и диапазоны сечений по изготовителю. Не закреплять как правило мнение «для электромеханического реле минимальный ток не важен».
7. Выбирать сечения по расчёту и зажимам. Сечения из любого учебного или прежнего проекта не являются универсальными значениями. Замена внутренних проводов не означает автоматической замены жил внешнего кабеля.
8. Уточнять обозначение DC: чёрный провод 0 В не называть −24 В, если отрицательного источника нет. Выбранные цвета хранить как проектный профиль и проверять применимость при новом задании.
9. Обновлять из одной модели Э3, монтажные адреса, карту клемм, таблицу соединений, перечень элементов и перечень сигналов. Спецификацию и перечень поставки сверять по точным артикулам и единицам, а не только по похожим названиям.

## Таблицы и закупка

Монтажная таблица: № записи; цепь; откуда: аппарат/вывод; куда: аппарат/вывод; сечение; цвет; шкаф; кабель/жила или примечание. Показывать непосредственный соседний конец, а не дальнюю точку, доступную через промежуточные клеммы. Длину не выдумывать.

Перечень элементов: позиция; наименование; модель/артикул; установленное количество; комплектность/число шкафов; закупка; запас; единица. Общий запас не умножать повторно на число шкафов. Колодки, защитные модули и удерживающие зажимы учитывать, если они действительно входят в проект; не восстанавливать все ранее удалённые принадлежности «на всякий случай».

Закупочная спецификация по запросу «просто таблицу»: один лист, нейтральные границы, без цветных заливок, титула с версией/датой, отдельного листа примечаний и пояснения цветов сверху. Не удалять содержательные примечания в столбце, если пользователь этого не просил. Для XLSX использовать действующий навык таблиц и его разрешённые средства.

Способ оконцевания не навязывать монтажнику: не добавлять требование двойного наконечника, если оно не задано. При этом допустимость количества и типа проводников в зажиме остаётся предметом проверки.

## Кабельные вводы

Считать переходы кабелей через стенки каждого шкафа, а не жилы, клеммы или строки таблицы. Один межшкафный кабель обычно требует ввод с каждой стороны. Внутренние кабели не создают внешних вводов. Проверить комплектацию проходного разъёма: отдельный гермоввод может требоваться или не требоваться по его конструкции.

Для каждого ввода хранить шкаф, кабель/группу кабелей, фактические диаметры, тип уплотнения и координаты отверстия. Запас показывать отдельно. Многокабельное уплотнение сохраняет кабели; коробка с общим многожильным кабелем меняет внешние соединения и добавляет собственные клеммы/вводы. Эти варианты не считать одной и той же правкой. Не снижать количество в спецификации без раскладки.

Размеры, рабочие токи, режим безопасности, количество вводов и соответствие стандартам не подтверждаются только успешным запуском скрипта.

## Размеры и проверка выпущенных документов

Разделять `enclosure_mm=[ширина, высота, глубина]`, `panel_mm=[ширина, высота]`, `door_mm` и физический размер бумаги. Для панели указывать начало координат внутри корпуса; для каждого аппарата — габарит, источник, положение, поверхность и зазоры. Не подставлять размер панели учебного корпуса в реальный артикул.

Для размерной компоновки и состава выполнять `audit_assembly.py`. Он проверяет данные, а не достоверность источника, электрические расчёты или глубину размещения. Отдельно проверить реальные колодки, монтажные отверстия, допустимость зазоров, глубину и ход двери.

Для полного комплекта адаптер генератора должен записывать `release.json`: хеш текущей модели, перечень файлов с хешами, фактически выпущенные строки соединений/закупки, размеры видов, размещённые позиции и доказательства таблиц. Затем выполнять `audit_release.py`. Контракт показан в `scripts/build_validation_fixture.py`; его выходной `release.json` используется только для проверки инструмента. Исторический набор X2002 имеет собственные модели и `set-manifest.json`, проверяемые `verify_reference_set.py`.

Не создавать отчёт вручную только ради прохождения проверки. Табличные доказательства включают прямоугольники ячеек в миллиметрах бумаги: проверка читает их обратно из конечного PDF. При другом формате или системе проектирования написать подходящий адаптер; не объявлять непроверенный экспорт проверенным. Для отдельного фрагмента проверять только его фактический объём, явно указав границу проверки.
