# Построение и форматы данных

## Векторный генератор

`scripts/drawing.py` сохраняет принятые векторные примитивы оформления. Требуются Python с reportlab, PyMuPDF (`fitz`), ezdxf. Предпочитать зависимости действующей среды. Шрифты DejaVu Sans с лицензией включены в `assets/fonts`. Проверенные версии среды записаны в `assets/rendering-environment.json`. Генератор не запускает внешние программы и не обращается к сети.

Все координаты примитивов — миллиметры бумаги, X вправо, Y вниз от верхнего левого угла. Размер шрифта `h` — приблизительная высота заглавной буквы в миллиметрах, как в принятом исходнике. Масштабировать геометрию изделия отдельно; не масштабировать рамку, тексты и штамп.

```python
import sys
from pathlib import Path
sys.path.insert(0, str(SKILL_ROOT / 'scripts'))
from drawing import Sheet

s = Sheet(1, 'Дискретные сигналы', 'A3', revision='1', total=1,
          out=WORK / 'output', terminal_style='circle',
          metadata={'designation':'PROJECT.Э3', 'object':'Шкаф управления'})
s.heading(28, 49, '1.1  Входы ПЛК', 370)
s.rect(270, 70, 60, 85, .5)
s.t(300, 80, 'A1', 3, True, 'center')
s.ln(180, 110, 270, 110)
s.term(180, 110, 'ШС1.XT1:1')
s.t(218, 107, '20', 2.5, a='center')
s.t(265, 117, 'Пуск', 2.5, a='right')
s.pin(270, 110, 'ШС1.A1@L01', '20', 'X0', side='left')
s.t(300, 111, 'X0.0', 2.5)
# Добавить реальную внешнюю часть и прочие цепи из текущей модели.
s.finish()
```

Это пример API, не полный электрический лист. Не выдавать пустую рамку или один незавершённый фрагмент вместо заказанного комплекта. В новом проекте реквизиты брать из задания; не оставлять `PROJECT` как фактическое обозначение.

| Метод | Назначение |
|---|---|
| `ln(x1,y1,x2,y2,w=.35,layer='WIRE',dash=False)` | Отрезок; электрические линии обрезаются по окнам клемм и в PDF, и в DXF. |
| `poly(points,...)`, `rect(x,y,w,h,...)` | Ломаная и прямоугольник. Использовать `MECHANICAL` для контура шкафа и размерной геометрии. |
| `t(x,y,text,h=2.5,b=False,a='left',rot=0,layer='TEXT')` | Надпись с фактической оценкой ширины; выравнивание left/center/right. |
| `term(x,y,label,below=False,pin=None,net=None)` | Клемма. `terminal_style='circle'` для управления, `'rectangle'` для силового/обзорного листа. |
| `pin(x,y,id,net,label=None,side='left')` | Точка вывода и заводская надпись; уникальный `id` может отличаться от надписи. |
| `contact(x,y,tag,pins=('11','14'),nc=False,ref='',push=False)` | Контакт с явными выводами; выбирать НО/НЗ по фактическому аппарату. |
| `coil(x,y,tag,left='A1+',right='A2−',model='',internal=False)` | Катушка; полярность и защиту задавать только по подтверждённой модели. |
| `link(x,y,net,page='2.1',to=True,length=24)` | Продолжение с явным адресом; номер листа без участка не принимается. |
| `table(x,y,widths,headers,rows,...)` | Таблица с переносом текста; высота растёт, поэтому проверить доступную область. |
| `finish()` | PDF, DXF, SVG и JSON геометрии в заданном `out`. |

Примитивы не выполняют автоматическую разводку и не выбирают номиналы. Надписи, которые проходят через провода, не исправляются белой заливкой: переместить текст или маршрут. Порядок вывода текста над символами и чистый DXF проверить после экспорта. Шрифты для редактирования DXF доступны в `assets/fonts`.

Вместо глобальных догадок `section_for` требует точную строку `лист.участок`; генератор не выводит адрес из номера цепи. Для набора листов использовать разные `n`/`basename`, общие данные и реестр участков. При создании нескольких проектов одним процессом очистить глобальные `SHEETS`, `PINS`, `REFERENCES`, `SECTIONS` либо запускать отдельный процесс на проект.

## Модель для audit_project.py

Рабочий образец: `assets/templates/model-example.json`. Он вымышленный и проверяет структуру одной межшкафной цепи; не является типовой схемой подключения конкретного ПЛК.

- `devices`: `id`, `model`, `cabinet`.
- `ports`: уникальный `id`, `device`, точный `factory_label`; необязательно `side`, `order`, `address`, `net`, `kind='terminal'`.
- `connections`: `id`, `from`, `to`, `net`, `scope='internal'|'external'`. Внутренний: `cabinet`, `section_mm2`, `color`. Внешний: `cable`, `core`.
- `cables`: `id`, `cores=[{'id':'1','spare':false}, ...]`. Каждая занятая жила имеет одну запись от конца до конца, резервная не подключена.
- `terminals`: `id`, `cabinet`, `group`, `number`, `ports`, `spare`. Порядок массива — физический порядок обзора.
- `sheets`: `id`, `sections=['1.1',...]`.
- `references`: `from`, `to`, `net`, при наличии `source_port`, `destination_port`.
- `wire_labels`: `connection`, `text`, `segment_from`, `segment_to`. При `require_wire_labels=true` каждый внутренний провод имеет запись маркировки своего отрезка.

Если задача ограничена оформлением фрагмента, не подбирать неизвестные сечения, цвета или жилы ради прохождения проверки. Оставить неизвестное явно незаполненным и отделить успешную проверку графики от неполной инженерной модели. Не закрывать этот пробел вымышленными данными.

Для используемого CAD/исходника допустим адаптер к этому формату. Не объявлять проверенной модель, вручную упрощённую так, что она потеряла существенные выводы. Совпадение текстового назначения маркировки не доказывает её геометрическое положение: отдельно проверить рисунок.

`audit_project.py` не проверяет закупочные количества и инженерные расчёты. Сверять их по `engineering-sync.md`. Скрипты используют код возврата 2 при выявленных проблемах; пустая модель тоже не проходит.

## Устойчивое воспроизведение

Сохранять вместе: модель, параметры оформления, исходник, шрифты/лицензию, версии библиотек, PDF/DXF, отчёт проверок и список принятых листов. При повторном запуске использовать те же физические размеры. Для печати испытывать конечный PDF, не только SVG. Учебный исходник отделён от общего инструмента. `build_demo.py` строит только вложенный учебный пример; для нового задания использовать `init_project.py` и свои данные, а не подменять имена в учебном генераторе.

После изменения инструментов выполнить `python scripts/self_check.py`: проверяются в том числе пропущенные клеммы, маркировка до местной клеммы, занятые резервные жилы и наложения. При обычной работе запускать только проверки затронутой задачи.

## Размерная модель и экспорт

Для `audit_assembly.py` использовать `cabinets`, `placements`, `mechanical`, `bom` из `assets/demo/project.json`. Источники условных размеров отмечены как учебные. В реальном проекте вместо них указать проверенные размеры точного артикула. `clearance_mm=[слева, сверху, справа, снизу]`, `bbox_mm=[x0,y0,x1,y1]`; все величины здесь относятся к изделию, не к бумаге.

Для `audit_release.py` адаптер записывает сведения о действительно нарисованных видах и экспортах. Файл выпуска учебного примера демонстрирует контракт, включая таблицы с адресами ячеек и обратным чтением из PDF. Хеш модели обнаруживает выпуск по старым данным. Скрипт не доказывает правильность электрической работы условных аппаратов и не заменяет просмотр страниц.

Включать интерфейсы как отдельные записи `interfaces`: кабель Ethernet не описывать одной вымышленной физической жилой. Для каждой пары концов проверять существование портов и границы шкафов отдельно от обычных проводников.

При `bom_include_cables=true` проверка состава требует каждую запись кабеля/интерфейса в BOM с явными `part` и `quantity`. Количество кабелей задаётся на комплект явно; число жил не является количеством закупки.
