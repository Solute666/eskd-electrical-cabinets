# Электрические и монтажные схемы ЕСКД

Воспроизводить принятый способ чтения и оформления схем, а электрическое содержание определять по текущему заданию и документации оборудования. Навык самодостаточен: общие требования исходного `eskd-drawings` включены ниже, обязательной зависимости от его установки нет.

## Начать с нужных источников

1. Прочитать актуальные файлы и последние решения пользователя. Определить: какой шкаф/комплект, какие листы затронуты, что уже принято, где действующая спецификация, какие реквизиты известны. Не подменять их учебным примером.
2. Прочитать [правила оформления](references/presentation.md) и [правки и проверку](references/revisions-qa.md). При изменении соединений или состава прочитать [согласованную модель](references/engineering-sync.md). При размещении аппаратов обязательно прочитать [монтажную компоновку](references/mounting.md).
3. Открыть нужные страницы вложенного образца по [указателю примеров](references/examples.md), а не весь архив подряд. Использовать `scripts/render_reference.py`. Не ограничиваться извлечением текста из PDF.
4. Прочитать [границы учебного примера](references/sample-scope.md). Для противоречивых указаний использовать [принятые решения](references/decisions.md). При подготовке публичного пакета прочитать [публикацию](references/publication.md).
5. Уточнять только существенные неизвестные данные. Не угадывать модель, выводы, сечения, размеры, безопасность, фамилии и утверждения. Самостоятельно выполнять доступную часть работы до вопроса.

## Неизменные принципы

- **Клеммы:** в управлении круглые; на силовой схеме и отдельных листах клемм прямоугольные. Показывать физически необходимые клеммы, не добавлять распределительные блоки для каждой местной связи.
- **Маркировка:** внутренний номер на участке местная клемма → аппарат. Перед местной клеммой показывать действительный внешний кабель/жилу/аппарат, а для другого шкафа — его границу и клемму. Не смешивать номер цепи со ссылкой, адресом ПЛК и номером жилы.
- **ПЛК:** на функциональном виде входы слева, выходы справа; DI/DO/AI/AO; функция возле провода; заводской вывод у контура, программный адрес отдельно. На монтажном виде сохранять фактическое расположение и порядок выводов устройства.
- **Связи:** короткие ортогональные маршруты; точки только в соединениях; ссылки `/лист.участок`; провод заканчивается на точке вывода. Позиция катушки отдельно, небольшая ссылка на её контакты — под символом, если уместна.
- **Комплект:** одна согласованная модель соединений и аппаратов; полный обзор внешних и внутренних клемм; реальный числовой порядок XT; резервы и экраны учтены. Э3, Э4, таблица соединений, перечень и закупочная спецификация согласованы.
- **Принятые листы:** не переделывать стиль и топологию вне затронутой задачи. Сравнивать неизменённые страницы с оригиналом. Более позднее частное указание не превращать в глобальную замену всего комплекта.
- **Графика:** точная векторная геометрия; рамка и основная надпись на каждом графическом листе; физический формат и масштаб; читаемая кириллица. Проверять подходящую систему оформления и действующие требования по авторитетным источникам, не объявлять полное соответствие ГОСТ по сходству штампа. Не применять генерацию растровых изображений для точных схем.

## Выполнить работу

1. Составить короткую карту затронутых документов и зафиксировать границы правки. Продолжать текущий исходник, если он доступен и пригоден. Для нового проекта создать рабочую папку командой `python scripts/init_project.py TARGET --project NAME`; пустые данные заполнить по источникам.
2. Разнести факты оборудования и электрические связи от координат рисунка. Записать идентификаторы аппаратов, физических выводов, проводов, кабелей, жил, клемм и листов. Использовать существующий формат проекта или [пример модели](assets/templates/model-example.json).
3. Перед черчением согласовать содержание со спецификацией. При замене аппарата проверить последствия для колодки, контактов, выводов, питания, габаритов и закупки. Не вводить номиналы прежнего проекта или учебного примера как значения по умолчанию.
4. Разложить листы и участки, зарезервировать штамп и таблицы. Выбрать читаемый формат; не ужимать надписи ради одного листа. Для панели и двери использовать фактические размеры, координаты и зазоры; сохранять принятый принцип «короб — рейка — короб» там, где он применим.
5. Строить PDF и редактируемый источник одним набором координат. Использовать `scripts/drawing.py` и [инструкцию по построению](references/building.md) либо штатную систему проектирования пользователя. `build_demo.py` воспроизводит только учебный пример; для нового проекта использовать пустые данные и отдельный исходник.
6. Проверить модель и геометрию скриптами ниже. Исправить ошибки, визуализировать экспорт, просмотреть каждый изменённый лист целиком и важные места крупно. Сверить неизменённые листы. Отчёты скриптов дополняют проверку, а не заменяют её.
7. Сохранить согласованные итоговые файлы и редактируемые исходники в доступном пользователю месте по действующим правилам среды. Версию комплекта и отдельные сохранённые ревизии описать точно. Не писать в чертеже служебные инструкции о способе генерации и не выдавать DXF за файл КОМПАС CDW.

## Средства проверки

Команды выполнять из каталога навыка или с абсолютным путём к скрипту. Выходные файлы писать в рабочую папку проекта, не в установленный навык.

```bash
python scripts/render_reference.py assets/demo/output/demo.pdf --pages 2,5 --out WORK/qa/reference
python scripts/audit_project.py WORK/data/project.json --report WORK/qa/model.json
python scripts/audit_layout.py WORK/output/sheet_layout.json --report WORK/qa/layout.json
python scripts/audit_assembly.py WORK/data/project.json --report WORK/qa/assembly.json
python scripts/audit_release.py WORK/data/project.json --bundle WORK/output --report WORK/qa/release.json
python scripts/compare_pdf.py BEFORE.pdf AFTER.pdf --allowed-pages 1,2 --report WORK/qa/unchanged.json
python scripts/verify_references.py
```

Для полной проверки выпуска `audit_release.py` требует адаптер, записывающий `release.json` из фактически выпущенных данных; формат показан в учебном исходнике. Для отдельного листа проверять фактический объём, не дополнять его вымышленными данными.

У `audit_assembly.py` проверяются объявленные размеры, зазоры, размещение и закупочные количества; достоверность паспортных данных и глубина компоновки требуют отдельной проверки. У `audit_project.py` проверка относится только к явно представленной модели. У `audit_layout.py` — к записанной геометрии; допустимые пересечения классифицировать вручную. Не использовать нулевое количество ошибок в пустой модели или прежний отчёт как доказательство готовности. Для электрических расчётов, работы цепей безопасности, печати на конкретном принтере и соответствия стандартам нужны свои подтверждения.

## Выдать результат

Сообщить состав и конкретные изменения, выполненные проверки и существенные оставшиеся ограничения. Не обещать «100%» без основания. Для простой закупочной спецификации соблюдать запрос «одна таблица»: без декоративных заливок, титула, дополнительных листов и нижних комментариев. Проверять каждый экспортированный файл; не ограничиваться исходным скриптом.
